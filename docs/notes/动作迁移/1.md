# ComfyUI 舞蹈试穿动作迁移方案

本文整理 ComfyUI 中“人物锁定 + 舞蹈动作迁移 + 视频虚拟试衣 + 批量换装”的工作流选型和落地路径，目标是稳定产出不同服装、不同舞蹈驱动下的试穿视频。

## 方案边界

本文负责说明：

- 推荐优先验证的动作迁移工作流。
- 最终完整链路中各模块的职责。
- 自定义节点、模型和硬件的最低准备项。
- 从单流程验证到批量生产的落地顺序。
- 常见失败现象和优先排查方向。

本文不负责：

- 维护本项目 `catalog/` 配置真源。
- 自动下载模型或安装插件。
- 保证第三方工作流链接长期有效。
- 替代实际显存、模型版本和节点版本下的本地验证。

## 整体模型

舞蹈试穿视频不是单一“图生视频”节点能稳定完成的任务，而是由三个核心能力串起来：

```text
人物锁定：多视图人物图 + IP-Adapter，尽量保持脸、身材和身份一致
服装迁移：服装参考图 + 视频级 VITON，让衣服跟随人物运动
动作驱动：舞蹈视频 + Wan2.2-Animate Move 模式，让人物按视频动作运动
```

完整链路可以理解为：

```text
[多视图人物图：正面/侧面/背面]
  -> IP-Adapter 多视图锁定人物身份
  -> VITON-DiT 视频虚拟试衣
  -> Wan2.2-Animate Move 模式做舞蹈动作迁移
  -> TemporalDiff / 光流时序稳定
  -> RIFE 补帧
  -> 输出 mp4
```

关键判断是：如果只需要“人物跟着跳舞”，Wan2.2-Animate 基础动作迁移即可；如果需要“换衣服后跳舞”，必须在动作迁移前接入视频级试衣链路。

## 推荐工作流

### 1. Wan2.2-Animate 官方动作迁移

这是基础验证工作流，应优先跑通。

- 官方文档和工作流入口：<https://docs.comfy.org/tutorials/video/wan/wan2-2-animate>
- 在页面中下载 `Download Workflow`，将 JSON 拖入 ComfyUI。
- 模式选择 `Move`：输入人物参考图和舞蹈驱动视频，输出人物跟随舞蹈运动的视频。

注意：这个原生工作流只负责动作迁移，不包含试衣模块。它适合作为第一步验证 Wan2.2-Animate、显存、节点和视频输出是否正常。

### 2. Wan2.2-Animate + 循环节点批量换装

这是最贴近批量生产试穿视频的方案。

- 参考项目：B站 `BV1QsoLB6EfU`
- 工作流下载：<https://pan.quark.cn/s/59bafd8bf39d>
- 核心能力：通过 MieNodes 循环节点遍历多套服装图，用一段舞蹈驱动视频自动输出多套服装对应的跳舞视频。

推荐链路：

```text
多视图 IP-Adapter 锁定人物
  -> VITON-DiT 视频试衣
  -> Wan2.2-Animate 动作迁移
  -> RIFE 补帧输出
```

该方案适合在基础动作迁移跑通后再接入。不要一开始就把批量循环、试衣和动作迁移全部混在一起排错。

### 3. SCAIL-2 长视频动作迁移

当舞蹈片段超过 10 秒，且基础工作流容易出现长时序脸部漂移时，可以评估 SCAIL-2。

- RunComfy 工作流页面：<https://www.runcomfy.com/zh-CN/comfyui-workflows/scail-2-motion-transfer-in-comfyui-reference-image-to-video>
- 适用场景：15-60 秒舞蹈片段。
- 主要优势：长视频人物一致性相对更稳。
- 主要代价：显存和运行成本更高。

## 必备依赖

### 自定义节点

优先通过 ComfyUI-Manager 搜索安装：

1. `ComfyUI-KJNodes`：Wan 相关工作流常用依赖。
2. `comfyui_controlnet_aux`：姿态、深度等预处理。
3. `ComfyUI-IP-Adapter`：多视图人物锁定。
4. `MieNodes`：批量循环换装。
5. `VideoHelperSuite`：视频加载、保存和帧率处理。
6. `VITON-DiT` ComfyUI 节点：视频级虚拟试衣。
7. `ComfyUI-RIFE`：帧插值和流畅度增强。

### 核心模型

1. `Wan2.2-Animate-14B fp8`：优先选择显存压力较低的 fp8 版本，例如 `Kijai/WanVideo_comfy_fp8_scaled`。
2. `IP-Adapter plus` 和 face 相关权重：用于多视图人物锁定。
3. `VITON-DiT` 视频试衣权重：用于动态试衣，不建议用图片试衣模型替代。

### 硬件与测试规格

- 最低建议显存：12 GB。
- 更舒适显存：16 GB 及以上。
- 8 GB 显存只能尝试 fp8 量化版本，时长和分辨率都需要明显压低。
- 首次测试建议分辨率：`720x1248`。
- 首次测试建议帧数：`30-42` 帧。

不要第一次就跑长视频。先用短片段确认人物、服装、动作和输出链路都成立。

## 落地顺序

### 路线 A：分开调试后合并

推荐优先采用这条路线，排错成本最低。

1. 跑通 Wan2.2-Animate 官方基础动作迁移。
   - 输入：人物参考图 + 舞蹈视频。
   - 验证：人物能跟随动作，脸和身材没有明显漂移。
2. 单独调试 VITON-DiT 视频试衣。
   - 输入：人物素材 + 服装参考图。
   - 验证：衣服能稳定贴合人物，运动中不明显穿模。
3. 将试衣输出接入 Wan2.2-Animate。
   - 验证：试衣后的人物能继续完成动作迁移。
4. 接入 MieNodes 循环。
   - 验证：同一段舞蹈驱动可以批量输出多套服装结果。
5. 最后补充 TemporalDiff、光流或 RIFE。
   - 验证：减少闪烁，提高帧间连续性和成片流畅度。

### 路线 B：直接使用整合工作流

如果目标是快速复现，可以直接下载整合好的循环换装工作流，先跑通样例，再替换自己的素材。

替换顺序建议：

1. 先替换舞蹈驱动视频。
2. 再替换人物多视图图像。
3. 最后替换服装图。

每次只替换一类输入，避免多个变量同时变化导致无法定位问题。

## 输入素材要求

### 人物参考图

- 建议准备 2-4 张多视图人物图。
- 至少包含正面；有条件时补充侧面和背面。
- 人物主体应清晰、无遮挡、光照稳定。
- 不建议只用单张参考图做批量生产，身份漂移概率更高。

### 舞蹈驱动视频

- 人物尽量居中。
- 背景尽量简单，纯色背景更利于稳定迁移。
- 动作不要一开始就选择大幅遮挡、快速旋转或多人同框素材。
- 先用短视频确认链路，再扩展到长视频。

### 服装参考图

- 服装主体应完整、无遮挡。
- 图片尽量正视、平整，减少夸张褶皱和复杂遮挡。
- 同一批次服装图尽量保持尺寸、构图和背景风格一致。

## 常见问题

### 人物漂移或变脸

优先检查：

- 是否只使用了单张人物图。
- IP-Adapter 是否接入到关键采样链路。
- 人物参考图是否包含足够多视图。
- IP-Adapter 权重是否过低。

经验范围：IP-Adapter 权重可以先从 `0.7-0.8` 试起，再按结果微调。

### 衣服穿模或扭曲

优先检查：

- 是否误用了图片试衣模型。
- 是否使用了视频级 VITON-DiT 链路。
- 服装参考图是否缺少完整衣服轮廓。
- 舞蹈动作是否过大，导致局部遮挡和形变过强。

### 视频闪烁或抖动

优先检查：

- 是否启用了时序稳定节点，例如 TemporalDiff 或光流相关节点。
- 是否在结尾使用 RIFE 做帧插值。
- 首测帧数是否过长。
- 驱动视频背景是否过于复杂。

### 想复现短视频平台上的口哨舞效果

这类效果通常是基础 Wan2.2-Animate 动作迁移：输入一张人物图或人物参考图，再输入口哨舞驱动视频，输出人物跳舞结果。

它默认不包含试衣模块。如果要在口哨舞基础上换衣服，需要先接入 VITON-DiT 视频试衣，再把试衣结果进入动作迁移链路。

## 验收标准

整理工作流时可以按下面标准判断是否进入下一阶段：

1. 基础动作迁移可以稳定输出短视频。
2. 人物身份在短视频中没有明显漂移。
3. 单套服装的视频试衣结果没有明显穿模。
4. 试衣结果接入动作迁移后仍能保持服装和人物一致性。
5. 批量循环能按服装列表生成多条视频。
6. 输出视频经过补帧或时序稳定后没有明显闪烁。

只有当前阶段达标后，再接入下一层能力。否则优先收缩变量，回到上一个可工作的最小链路排查。
